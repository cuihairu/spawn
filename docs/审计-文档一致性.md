### 结论：缺陷成立，已修

- **在真实产物上确认**（非推断）：下载的 `spawn-gateway-nightly-linux-arm64.rpm`
  `rpm -qip` 报 `Architecture: x86_64`，而其**载荷**是真 `ELF 64-bit … ARM aarch64`
  （`rpm2cpio | cpio -idm` 后 `file` 实测）。即载荷对、元数据错——arm64 主机
  `rpm -i` 会因架构不符拒装。这正是第三席位预判的失效模式。
- **修法取舍**：台账建议的「spec 加 `Arch:`」经实测**不可用**——rpm 6.0.1 报
  `error: line 7: Unknown tag: Arch: x86_64`（`Arch` 不是 rpm 的合法 spec tag，
  `BuildArch` 则报 `No compatible architectures found for build`）。改为
  `rpmbuild -bb --target "$RPM_ARCH"`：实测 `ARCH=aarch64` / `ARCH=x86_64` 各自正确。
  这是三条候选里唯一干净的一条。
- **加架构断言（两道）**：
  1. `scripts/nightly-packages.sh` 产出后立即 `rpm -qp --queryformat '%{ARCH}'` 比对期望，
     不符则 `exit 3` 并删除产物——负向测试（临时造一份漏 `--target` 的副本）实测
     打印 `rpm arch: x86_64 (期望 aarch64)` → `rpm 架构不符，拒绝产出`，arm64 rpm 未产出，
     脚本退出码 3。
  2. `nightly.yml` 冒烟步骤逐架构断言交付面资产。对**当前线上资产**干跑可复现拦截：
     `rpm arm64: x86_64（期望 aarch64）→ 断言失败`。
- **连带回改**：第三席位为免责在 `README.md:23` / `README.zh.md:23` 补的「arm64 主机需
  `rpm -i --force`」句，根因修掉后已成**假陈述**，若留着会误导 arm64 用户去用不该用的旗标。
  已改为「arm64 的 rpm 元数据标 `aarch64`、deb 标 `arm64`，两个架构各自正常安装」。
- **验证方式**：本地以真 arm64 / amd64 二进制跑修后脚本，arm64 rpm 实测 `ARCH=aarch64`
  （修复前同一载荷为 `x86_64`）；amd64 回归 `ARCH=x86_64` 干净。
